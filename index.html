a plastic state-space architecture

A small language model that is not a transformer.

PSSA reads text one token at a time through a recurrent state-space layer, keeps a bank of episodic memories it can look things up in, and rewrites part of its own weights while it runs. Written in Rust from scratch: no PyTorch, no TensorFlow, no ML framework underneath.

01 · the difference

How it differs from a transformer

A transformer scores every pair of tokens in the context, so its cost per step grows with the square of sequence length and the whole context is re-read at every step. PSSA carries one fixed-size state along the sequence in a single left-to-right pass, and looks things up in a memory bank instead of re-reading the context, so cost grows linearly with length.

01 / cost

Linear cost, not quadratic.

No attention map: the cost of a step does not grow with context length.

deeper

A token touches a fixed state of d_m × d_s, not a KV cache that grows with every prior token. The bank adds a scan over its fixed capacity, so the block's per-token work stays bounded as context grows.

02 / memory

Episodic memory.

Fixed-capacity (key, value) slots written during the forward pass: round-robin overwrite, exact full-scan soft read. Not an ANN index.

deeper

512 slots, hyperbolic keys, Euclidean values. Every occupied key is scored for every read; the opt-in CPU top-k prototype reduces value mixing but still scans all keys. It is not constant-cost retrieval.

03 / plasticity

Plasticity.

Part of the weights updates every token while the model runs, so the model changes as it reads.

deeper

A low-rank adapter takes fast per-token updates, and a closed-form ridge step folds those changes back into the base transition matrix after an epoch. Reading alters the weights that will read the next token.

04 / verification

Checkable gradients.

A scalar reference path every batched kernel is differentiated against, verified to about 3e-8.

deeper

Every batched and parallel kernel is finite-differenced against the scalar path on every commit. The measured maximum disagreement is 2.98e-8, not a claim taken on trust.

02 · inside the block

One token in. One state forward.

The first half of PSSA is a selective diagonal state-space model: no attention map, no growing cache. The recurrence is deliberately conventional — the same family as S4 and Mamba — because the architectural claim lives in what happens to its output.

Write x for the layer-normalized token embedding. Three projections read off the token itself, which is what makes the recurrence selective rather than fixed: a per-channel step size, an input map, and an output map. The transition is diagonal, one rate per channel–state pair, kept negative by construction so the recurrence cannot blow up.

Discretizing that continuous system with the token's step gives the update. The state h carries across tokens and across chunk boundaries during training, so context is not re-read — it is held. The cost of each step is set by a fixed state, not by the length of what came before.

At initialization, each channel's sixteen rates sit on log-spaced timescales from about 1.5 to 200 tokens, in the spirit of HiPPO. One channel therefore starts out holding the last two tokens and the last two hundred at the same time. Training moves those horizons rather than discovering them from scratch.

No novelty claimed here. The recurrence is selective-SSM machinery written out scalar-first so its backward pass can be checked term by term. The memory read on y is where PSSA diverges.

cost

One pass, no attention matrix.

Every token advances the same fixed-size state. Nothing is scored against every other token, so per-token work does not grow with context.

horizons

Timescales at initialization.

Sixteen states per channel, log-spaced from 1.5 to 200 tokens. Short and long horizons coexist before training has moved anything.

selection

The read is conditioned on state.

The memory query is formed from the current token and the current recurrent state, so retrieval depends on where the sequence has arrived.

03 · episodic memory

A bounded read, not a search index.

PSSA keeps a fixed-capacity bank of 512 episodic memories, written during the forward pass. Keys are projected inside the Poincaré ball; values stay Euclidean. Every read is exact, and the query is conditioned on both the current token and the recurrent state.

the read exact · every occupied slot

A query is formed from the token and the state, then mapped diffeomorphically into the ball. Hyperbolic distance grows sharply toward the boundary, so a key for general context and a key for one specific episode stay separable without widening either key. The read is a softmax-weighted mix of values.

write path

Fixed at 512. Overwritten on purpose.

The write head advances round-robin to the next slot. A novelty check gates insertion, and a refractory counter rate-limits how often a slot can be overwritten, so repeated evidence stabilizes a slot against a contradictory stream.

key geometry

Distance separates the general from the specific.

Keys live on the Poincaré ball; values are Euclidean. Distance rises sharply near the boundary, so broad context and one-off episodes can occupy the same bank without sharing the same neighborhood.

consolidation

Fast writes folded into the base.

A closed-form ridge step folds accumulated plastic updates into the transition matrix, so long-range structure does not live only in the external store.

Abase←Abase+ (HTH+λI)−1 HTΔH

Exact by default; top-k is a prototype. The default read scans every occupied slot and normalizes over all of them. The experimental CPU --memory-top-k K path still scans every key, then renormalizes the softmax on the K nearest. It reduces value mixing, not the scan; it is not an ANN index and not constant-cost retrieval.

04 · plasticity & verification

It changes while it reads.

A language model usually freezes when training ends. PSSA keeps a fast plastic path: part of the weights updates every token, and the memory bank absorbs episodic writes during the forward pass. The base transition matrix only moves through a closed-form consolidation step.

the per-token gate learned
g=sigmoid(wgate·x)

The read does not join the residual stream unconditionally. A learned per-channel gate, computed from the current token, decides how much retrieved memory lands. A rank-16 SiLU adapter carries targeted fast updates alongside it.

read m gate g residual z adapter SiLU MLP

two speeds of change

Fast per token, slow per epoch.

The adapter and the memory bank change inside the forward pass. The base transition matrix is updated separately by the ridge step, so fast evidence and lasting structure do not have to share one timescale.

gradient verification checked every commit
2.98e-8max disagreement

A scalar reference path computes the same gradient by hand. Every batched and parallel kernel is finite-differenced against it; the largest disagreement measured is this number, around the claimed 3e-8.

why it matters

The model is not a fixed function of its context.

Reading can change what the next read retrieves. Memory writes are gated by novelty and refractory counters, while fast weight changes are folded back into the base transition by A_base ← A_base + (HTH + λI)−1HTΔH.

why it is checkable

Every shortcut has a reference.

The linear algebra is written directly, with no autograd framework deciding what the gradient means. That makes the hand-derived backward pass testable against the scalar path term by term — not just until the loss goes down.

Scope note. Plasticity here means a fast adapter and gated memory writes during the forward pass, plus ridge consolidation of those updates. It is not a claim that the full model is retrained at inference time, or that every parameter changes on every token.

What this does not prove: these numbers come from one corpus and one training seed, measured by the author, at 1.5M-parameter scale. No third-party replication yet. A larger run is in progress. Full provenance: the README's comparison section, github.com/Sparticle62ops/pssa.
Reading the comparison honestly: text quality at this scale is poor for both models; the result is about learning efficiency, not fluency. The headline training-speed figures came from different machines and are not hardware-matched — the 4.13× throughput figure above uses the same 2-vCPU box and the same 199,059-token slice. Two experiments remain unmeasured: retention of earlier skills after a corpus switch, and whether ablating the 512-slot memory bank changes the loss.
