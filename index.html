Research prototype · state-space language model

A language model that remembers, then rewrites itself.

PSSA is a 1.54M-parameter prototype that replaces attention with a fixed-size recurrent state, adds a bounded episodic memory, and folds experience into its weights through closed-form consolidation. It is not a general-purpose model. It is a small, inspectable proof of a different way to carry context.

01 · Overview

Three ideas, one small block.

PSSA is built around a persistent state, an episodic memory with a hard size limit, and weights that can absorb experience during training. Each mechanism is deliberately small enough to measure, ablate, and inspect.

The result is not a faster transformer impersonator. It is a different accounting of context: carry a state, look things up, and consolidate what matters.

01recurrent core

A state instead of a window

A selective diagonal state-space recurrence carries 256 × 16 values left to right. Every token updates that state once; no context window is re-read and no attention matrix is built.

ht = fθ(ht−1, xt)

02episodic memory

Memory with a boundary

512 episodic slots hold keys in a Poincaré ball and values in Euclidean space. Reads are an exact softmax over every key; writes rotate round-robin, so the bank can never grow.

m = Σs wsvs

03plasticity

Weights that move

A rank-16 adapter shapes every block output. At consolidation boundaries, a ridge solve folds accumulated statistics into a base matrix — a weight update with no second backward pass.

Abase ← Abase + ridge(H, ΔH)

Scope. PSSA is a 1.54M-parameter research prototype, trained once on a small corpus and measured against a size-matched baseline. Read the numbers as an existence proof, not a production claim. The method and the limits are part of the result.

02 · Architecture

One token, five moves.

Everything is computed once per token, left to right. No context window is re-read and no attention matrix is materialized. Step through the block below, or turn on narration and listen.

The equations are the actual operations, simplified only where the deep dive goes further: the memory read is a full scan by default, and consolidation runs at explicit boundaries.

Phase 01 · project

A token becomes a vector.

The token ID indexes a 2,048-entry embedding table. The resulting 256-dimensional vector is the only thing the recurrent core sees; there is no context window to re-read and no positional attention to compute.

embedding

xt=E[tokt]∈ℝ256

2,048-entry vocabulary · 256 latent dimensions per token

Phase 02 · selective recurrence

The state is updated, not rebuilt.

A diagonal selective state-space layer carries the context. Its step size, input projection and output projection are read from the current token, so each channel can open slowly or close quickly from one step to the next. The update is elementwise, and total cost stays linear in sequence length.

selective SSM

δt=softplus(Wδxt) At=exp(δtA),Bt=δtBt ht=At⊙ht−1+Bt⊙xt

A 256 × 16 state persists between tokens · 16 log-spaced time constants, 1.5–200 tokens

Phase 03 · episodic read

Look up the past by distance.

The query mixes the current token with the recurrent output. It is projected inside a Poincaré ball, where distance grows toward the boundary and can encode hierarchy. The read scans every one of the 512 keys, scores them by hyperbolic distance, and mixes their Euclidean values.

full-scan read

qh=proj(Wqxxt+Wqhht) w=softmax(−dH(qh, ks)τmem) m=Σswsvs

512 hyperbolic distances per read · optional top-k still scans all keys, then mixes only K values

Phase 04 · adaptation

Mix, adapt, consolidate.

A sigmoid gate decides how much of the memory read enters the block. A rank-16 adapter then makes a learned correction. At consolidation boundaries, accumulated statistics are solved rather than gradient-stepped: the base weights absorb a closed-form delta.

gate and adapter

g=sigmoid(wgate·xt) A(xt)=W2silu(W1xt)
Abase←Abase+(HTH+λI)−1HTΔH

Rank-16 adapter · ridge consolidation folds accumulated input/output statistics into the base matrix

Phase 05 · prediction & write

Predict, then decide what to keep.

The adapted block output is projected to the 2,048-token vocabulary. After the step, the state summary becomes a candidate key and value. A round-robin target slot accepts the write only when the entry is novel enough and the slot has cleared its refractory window.

vocabulary projection

pt=softmax(Woutzt)

z is the adapted block output · writes require novelty above a threshold and a target slot outside its refractory window

03 · Evidence

Small scale. Real measurements.

One seed. 12.7M cleaned WikiText-103 tokens. A 1.54M-parameter PSSA and a parameter-matched transformer trained under the same 30,000-update cosine horizon, then evaluated on 198,939 held-out tokens neither model saw.

What this does not prove

The limitations are part of the result, not a footnote. Read them before generalizing from any number on this page.

  • Scale. Both models are 1.5M-parameter prototypes. Text quality is poor at this size, for PSSA and the baseline alike.
  • Evidence. One seed, one cleaned corpus slice. There is no memory-bank ablation yet and no measured skill-retention test after a corpus switch.
  • Hardware. Training rates are not all hardware-matched. The table labels the CPU pair; the T4 probe has no transformer counterpart.
  • Dreaming. The experimental consolidation mode is off by default and is not part of the headline results.
  • Novelty. The selective state-space layer is established machinery. The specific claims are the state-conditioned hyperbolic read, the novelty and refractory write gates, and ridge consolidation.

Questions people actually ask

Why no attention?

Attention costs grow with context length. PSSA carries a fixed-size state, reads a bounded memory with an exact full scan, and writes with a round-robin slot policy, so per-token cost stays flat no matter how far the context reaches back.

Is this a transformer replacement?

No. It is a different accounting of context, tested at prototype scale against a parameter-matched baseline. The comparison is deliberately narrow and the limits are written down.

What can it not do?

At 1.5M parameters, text quality is poor for both PSSA and the baseline. One seed, one corpus, no memory-bank ablation yet. Those are the honest edges of the result.

Where do the numbers come from?

From the repository: the training logs, the 64-checkpoint loss series in loss.csv, and the evaluation scripts that produced the held-out figures. Re-run them and you get the same table.
